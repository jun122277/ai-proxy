# ADR-0001: 小さな Streaming サービスで運用判断を検証する

- 状態: Accepted
- 日付: 2026-09-23
- 対象: [開発ロードマップ](../ROADMAP.md) の M0〜M7

## 背景

SRE ポートフォリオとして、外部依存の障害、過負荷、長寿命接続、リリース失敗への対処を再現可能な形で示したい。多数の LLM 機能を実装すると、障害試験と運用の改善履歴に使える時間が減る。

## 決定

Go の標準ライブラリを中心に小さな HTTP サービスを作る。初版はテキストのみの Chat Completions 互換 API に限定し、実装前からその対応範囲を明示する。主系/副系は同じプロトコルのモックを使い、通常の CI と GameDay で実 API を呼ばない。

M0 は設定検証、HTTP プロセス、`/healthz`、期限付き終了、コンテナと CI までとする。`/readyz`、認証、upstream、SSE は M1 で実装する。M0 のヘルスチェックはプロセスの生存だけを意味し、生成要求を処理できることを示さない。

非秘密の起動設定は JSON とし、不明キー、重複キー、null、不正な値を拒否する。YAML の追加依存はこの段階で導入しない。秘密は M1 以降に環境変数/Secret から読み込み、設定やプロンプトをログへ丸ごと出さない。

Compose を開発環境の基準にする。Windows では Docker Desktop の Linux コンテナを用い、Go/Make を持たないホストでも開発用コンテナで検証できるようにする。Kubernetes は M5 で追加し、最初から開発時の必須条件にしない。

Go のバージョンとコンテナの digest、CI action の commit を固定する。PR で format/vet、race test、ビルド、到達可能な Go 脆弱性、実行イメージの HIGH/CRITICAL 脆弱性を検証する。イメージは non-root、Compose では読み取り専用・capability なしで起動する。

## 比較した案

| 案 | 今回の判断 |
| --- | --- |
| 多数の実プロバイダ、管理 UI、セマンティックキャッシュから作る | 初期スコープ外。障害対応の証拠を先に揃える |
| 最初から Kubernetes/GitOps を必須にする | M5/M6 で導入。M1〜M4 は Compose で再現可能にする |
| ホストへ Go/Make を必須インストールする | 任意。開発用コンテナを同じ検証手順への入口にする |
| 依存先障害を成功率から除く | 不採用。利用者向け SLO に含め、原因は内訳として分類する |

## 結果と見直し条件

M0 だけでは AI API ゲートウェイとして使えない。その制限を README と HTTP の応答で明示する。ベンチマーク値は測定後に掲載し、短いローカル試験を本番の30日 SLO 実績として扱わない。

JSON で設定表現が不足する、複数チームで編集が必要になる、または動的設定が必要になる時点で設定方式を見直す。SSE と切断伝播の契約が固まる M1、リトライを加える M3、クォータを加える M4、デプロイ制御を加える M5/M6 では個別 ADR を追加する。
